# Rendering differences and lifecycle acceptance

This is an independent source audit for the unified museum's first real adapter slice: coffee and fan. It is not a claim that all ten exhibits have been migrated or that browser, visual, or assistive-technology acceptance has passed.

### Safe commonality, important divergence

1. All four `observation.js` files are byte-identical: 72 lines, SHA-256 `9761c10cea96cc8a0f6e4b293943a62b3f179c574377ef9d49c9f3c7192d8733`. One shared implementation is appropriate, with lifecycle/scoping adapters.
2. The audio source has **two** real versions. Fan, washer and claw share the 320-line `7a51add0b8a4c787c605afef4b9c4ed04ba913b64cb64439924850cd23d42aa3` version. Collection uses 326-line `fb054915b8db99f50cd4f12b0a33f9393fcfa668e8a88595a06c467109b4137a`. There is one diff hunk with three meaningful corrections: coffee `brewPaused` suppresses its loop; prepared milk uses a quiet `pour` only while `milkT` is between .25 and .75 rather than always implying a steam wand; camera `lessonPaused` suppresses its roller. Consolidating onto the older version loses real behavior.
3. Collection owns dynamic action labels/progress, action hints, audio attach/update, observer updates, and real-time camera steps unaffected by observation slowdown. Washer/claw use pressed-control metadata, feedback, configured home views, and their own scene integration. Neither older inline `mountFigure` provides a comprehensive unmount API.
4. Collection's focus recovery uses logical action plus duplicate index and falls back to the model when the control is unavailable. Claw additionally uses `data-i` to preserve toy identity, guards the `focusout` generated by redraw, and rejects hidden physical controls. Washer has the older replacement-only focus recovery. Do not flatten these into a lowest-common-denominator handler.
5. Claw reserves plain arrow keys for aiming and uses Shift+arrows for camera orbit. Collection and washer use plain arrows for orbit. Fan handles arrows and Space at its SVG root. This is a scene-specific input policy, not styling.
6. All three Colorfigures drivers use a set of step callbacks with a bounded dt and demand-driven RAF. Fan's driver analytically integrates acceleration, travel, coasting and head swing, with input-time settling and its own 50 ms cap. Replacing it with a nominal frame increment changes motion semantics.
7. The three Colorfigures entries contain module-like but document-global camera/projection/material state. Fan instead creates a `Paper3D` instance and uses a different projection. The unified project can share tokens and lifecycle without rewriting either renderer's geometry.

## Cross-scene hazards verified in source

### Host and global ownership

- Legacy `mountFigure` replaces `document.body.innerHTML`, sets `document.title`, queries document-wide IDs, and updates `<html>` classes/CSS. A unified adapter must mount into its explicit root and leave the shell/navigation intact.
- `window.__st`, `window.__fanState`, `window.__ui`, `window.__cfg`, `window.SCENES`, `window.Paper3D`, `window.MechanicalAudio`, and `window.MuseumObservation` expose document-wide ownership. A controller snapshot is safer than leaving previous scene state reachable as the current scene.
- Legacy `shell.js` intentionally reloads the document on scene hashes. The browser formerly cleaned up state, listeners and clocks. Removing reload without adding equivalent lifecycle cleanup changes the architecture materially.

### Scheduling and asynchronous callbacks

- Core `visibilitychange` listeners restart invalidation even after their scene DOM has gone. Fan additionally wakes on `pageshow`. Document visibility is not equivalent to scene activity.
- Flash timers, click-dedup release timers, delayed overflow measurement and URL-driven QA actions can run after replacement. Reset must invalidate old callback epochs, not only clear visible DOM.
- `bakeNoise` uses `Image.onload`, outside event/timer/RAF tracking. Its existing `t.isConnected` guard helps, but should be complemented by scene ownership when applying or releasing results.
- Audio `resume()` resolves asynchronously. The original audio implementation already checks an epoch and context identity. Preserve those checks through consolidation and test leaving while resume is pending.
- An idle scene must have no active RAF. An active scene may have at most one driver chain. Pause/resume must not accumulate chains or charge the hidden interval to simulation time.

### Input, focus and observation

- Fan relies heavily on `onclick`, `onpointer*`, `onfocus` and `onblur` properties. Tracking only `addEventListener` cannot isolate retained old DOM nodes. Remove/guard these handlers as part of adapter disposal.
- Pointer capture, current drag, pressed state, key ownership and compatibility-click suppression must be canceled together on pause/dispose. A pointerup after switching must not activate an old target.
- Restoring a scene control's focus during its normal redraw is correct; restoring focus during route disposal is not. `mountLesson` moves action nodes and its `place(false)` can restore focus to a summary. Route disposal must not steal focus from the new scene or navigation.
- The shared observation implementation has no independent motion clock, which must remain true. Its `dispose` removes document/window listeners and marks; it also resets rate through `onRate`, so cleanup order must avoid this callback restarting the scene.
- Observation's default `#fig` lookup and lesson's document-wide `#btns` lookup require explicit root ownership. A fan mounted beside a stale coffee DOM must never adopt the coffee action dock.

### Audio

- Sound remains opt-in and starts only from a trusted explicit toggle. Blur, hidden, pagehide and route departure mute it. Returning does not silently reopen or resume sound.
- The audio singleton's legacy `hashchange` listener disposes whichever panel is attached at callback time. With a live router this can destroy the **new** scene's audio panel, depending on event registration order. Route ownership belongs to the router/controller, not an additional global hash listener.
- `attach` returns a panel-identity-aware disposer. Keep this token: a stale controller's dispose must not close a newer scene's audio context or remove its controls.
- Audio disposal must invalidate a pending resume, stop voices, disconnect their graph and close its context. An enabled preference must not be mistaken for evidence that an audio graph is currently audible.

## Required controller behavior

The exact TypeScript method names can evolve; these invariants are acceptance requirements.

- **Mount:** Own one explicit root, obtain scoped resource/audio/observation ownership, create fresh physical state, render the actual exhibit, and avoid global DOM destruction. A failed or superseded mount must release everything it acquired.
- **Pause:** Idempotently prohibit new physical input, terminate pointer/key ownership and visual pressed state, pause simulation clocks and pending scene-owned work, and silence sound. Do not reset physical progress or pretend the mechanism's own pause button has been pressed.
- **Resume:** Only an active, non-disposed controller can resume. Use a fresh timestamp; never replay background wall time. Multiple pause reasons (e.g. route and hidden) must not release one another. At most one RAF chain resumes and audio remains off.
- **Reset:** Invalidate the old callback generation before restoring the scene's documented initial state. Old timers/RAF/input/async work cannot mutate replacement state or DOM. Camera-only reset and whole-exhibit reset must remain distinct.
- **Dispose:** Idempotently mark the controller terminal before invoking cleanup callbacks, cancel input/capture and all owned scheduling, dispose the observer and owned audio attachment, and release listeners/attributes. Remove only owned DOM, or hand its inert DOM back to the host for immediate removal. No outgoing focus restoration. Later reset, resume or old event dispatch cannot resurrect it.
- **Diagnostics/snapshot:** Report physical state and resource ownership without assigning new global debug state. Read-only snapshots must not expose mutable internal arrays/objects by reference.
- **Switch:** The application root and shared navigation design remain stable, and the outgoing controller is terminal before incoming input is enabled. The current router switches synchronously; any future asynchronous loader must prevent a stale pending load from winning. Browser history uses routes, not document reloads. Unmigrated exhibits must be identified honestly rather than represented as migrated because a legacy page exists.

## Red-test checklist for the real first slice

The executable lifecycle suite must import the actual adapted coffee and fan modules and the actual host switch path. It must not replace the mechanism with a toy controller or execute copied script excerpts as its subject. Controlled time, layout, pointer capture and audio nodes are legitimate environment doubles; physical state transitions and render functions are not.

1. Coffee and fan each render nonempty real SVG geometry and their original useful controls in a stable host, without an iframe, `eval`, or `new Function` bridge.
2. Coffee → fan → coffee while motion is active: no stale mutation, no stale RAF/timeout/window/document listener, one current controller, and fresh re-entry state.
3. Repeated mount/switch cycles: resource counts return to a stable baseline, not merely zero pending RAF at one instant.
4. Pause while active, wait, resume: physical snapshot stays unchanged while paused; no hidden-time catch-up; duplicate resume does not add drivers; idle eventually has zero frames.
5. Reset while a flash, input-dedup timer or animation is pending: old work cannot change new state or render after reset.
6. Dispose twice, then invoke old reset/resume, dispatch old DOM clicks/keys/pointerup, document visibility and window pageshow/blur: no revival and no effect on the new scene.
7. Pointer drag/capture and held-key cancellation across switching; independent later assistive clicks still work without duplicate activation.
8. Focus stays on the new scene/navigation after outgoing lesson cleanup. Redraw preserves logical control focus only inside the active scene.
9. One shared audio panel, no autoplay, switching with a pending audio resume is safe, old dispose cannot remove the new panel, and route hash events cannot silence a newly mounted attachment by stale ownership.
10. Observation reads physical state and shares its simulation rate; closing/disposal resets rate without scheduling independent progress or stealing the next scene's controls.
11. Existing coffee process and fan time-integration suites remain applicable. Full visual/browser/mobile/screen-reader claims require their own checks and are not implied by JSDOM lifecycle tests.

## Verification status

The independent first-slice audit is complete at this checkpoint. `tests/lifecycle-contract.test.ts` runs **25 passing tests** against the real modules:

- 7 shared-boundary tests: timer/RAF pause and remaining delay, terminal disposal, cleanup exception resilience, scoped queries, listener type/capture/duplicate identity, and native function/object callback ownership.
- 11 actual adapter/service tests: original SVG generation, surrounding-root preservation, overlapping pause reasons, physical input/motion freezing, no elapsed-time catch-up, reset and stale DOM isolation, fan pointer capture cancellation, observer input isolation, coffee transient-feedback reset, and held-key release for both exhibits.
- 4 actual host tests: coffee → fan → coffee with fresh re-entry state, rapid last-navigation-wins behavior, outgoing lesson focus isolation, and three repeated real-adapter cycles returning to stable scoped resource counts.
- 3 actual audio tests: pending trusted-toggle resume canceled across coffee → fan, stale attachment/hash-event isolation, and retained old toggle/volume controls remaining inert after a real route switch. The final case dispatches events on detached controls and invokes retained production callbacks, requiring both listener removal and attachment-identity guards. Only browser trust delivery and Web Audio nodes are fixtures; the production audio callback, epoch checks and routing are executed unchanged.

The tests first exposed real defects in cleanup after exceptions, listener identity/deduplication, coffee transient feedback reset, residual click suppression, and old audio controls mutating a newly mounted scene's sound service. Those tests now pass after the production fixes. Additional source review also prompted explicit observer handler ownership and preservation of listener `this` semantics.

Commands passed at this checkpoint:

```sh
./node_modules/.bin/vitest run tests/lifecycle-contract.test.ts
./node_modules/.bin/eslint tests/lifecycle-contract.test.ts
./node_modules/.bin/tsc --noEmit
```

This is JSDOM integration plus controlled-time/resource testing, not a browser or visual acceptance result. It does not assess raster appearance, mobile scrolling, screen-reader behavior, audible timbre, or device loudness. The router is synchronous, so the rapid-navigation test does **not** claim coverage of an asynchronous loader. A future asynchronous loader requires a dedicated superseded-load test. The other eight exhibits are not covered as migrated modules by this first slice.
