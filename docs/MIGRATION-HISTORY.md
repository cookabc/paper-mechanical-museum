# 迁移历史：从四套入口到统一应用

这份文档把原来分散在七份文件里的迁移记录合并成一份：四份分批验收
（2 → 5 → 8 → 10 件）与三份统一工程之前的静态交付包说明。它们描述的是
**已经完成的迁移**，不是当前状态。当前目录、命令与生命周期以
[开发与验收指南](DEVELOPMENT.md) 与实际源码为准。

其中出现的仓库名、分支名、路径、授权与测试数字只适用于对应阶段。

## 阶段一至四：分批接入（2 → 5 → 8 → 10）

四批的共同做法：每批基于上一批的远端提交，只新增展品适配，不改机械绘制
路径，不合并到 main、不发布生产。每批都在真实浏览器里用页面自己的按钮与
键盘操作，不注入模型状态。

| 批次 | 基线提交 | 新增 | 累计 |
| --- | --- | --- | --- |
| 首批 | `ae56905` | 咖啡机、电风扇 | 2 / 10 |
| 第二批 | `5c9636c` | 拍立得、售货机、烤面包机 | 5 / 10 |
| 第三批 | `8911e87` | 音乐盒、唱片机、电梯 | 8 / 10 |
| 最终批 | `2d80d2b` | 洗衣机、抓娃娃机 | 10 / 10 |

首批同时确立了工程基线：`npm run check`（ESLint、TypeScript、当前模块测试、
Vite 构建）成为每批的准入条件。

最终批之后的关键结论：

- **十件由同一个 Vite 应用真实挂载**，没有嵌套站点或 iframe。首页
  `/#/`，展品分别为 `/#/washer`、`/#/fan`、`/#/claw`、`/#/coffee`、
  `/#/musicbox`、`/#/vending`、`/#/toaster`、`/#/turntable`、`/#/camera`、
  `/#/elevator`。将来切换旧入口时必须保留展品 hash，而不只换域名。
- **两种「离开」并不相同**：退出原理观察只收起讲解，不销毁机器，重入保留
  进度与暂停状态；离开展品路由会终止场景、释放资源，重进从初始状态开始。
  后者不保存半杯、半程或未领取物品。
- 洗衣机与抓娃娃机各保留一个明确的历史渲染适配器，而不是把两套核心同名
  覆盖；它们与其余八件共用同一 SceneContext、ResourceScope、音效服务、
  原理观察组件与路由。
- 新增 14 项真实模型对照／生命周期回归（洗衣装衣加料运行暂停取衣；抓物
  落空、四只娃娃抓取领取、计数、多视角）。JSDOM 缺失的 `getScreenCTM`
  用明确布局 stub，不把它当真实浏览器几何测试。
- 产物边界：`npm run build` 后执行 `scripts/verify-build.mjs`，只允许
  HTML、哈希 JS、哈希 CSS 与模型 SVG 预览三类运行资产，拒绝 fixture、
  工作区绝对路径与原站 hosting 身份。

## 统一工程之前：静态源码交付包

以下描述的是**迁移之前**的形态，已被统一应用取代，保留仅供追溯。

- 旧形态是完整静态源码交付包：`object-collection/dist/shell.js` 加七个
  独立页面，每件展品各自入口，靠页面跳转而非路由切换。
- 当时的交付范围与最小适配清单按页面逐个列出，验收也按页面进行；这套
  划分在统一应用里不再成立。
- 当时的测试与可移植性说明针对上述静态包；当前测试见
  [测试与可移植性](TESTING.md) 与 `npm run check`。
